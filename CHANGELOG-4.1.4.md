# SAPL 4.1.4

This release restricts how the policy engine resolves references between JSON schemas. Apart from that, the code is unchanged from 4.1.3.

A JSON schema can name another schema with `$schema` or `$ref`. Schemas reach the engine through `schema` statements in policies, through the `schemas` variable of the PDP configuration, and as arguments of the `jsonschema` function library, whose arguments can come from an authorization subscription or from attribute data. Up to 4.1.3 the engine passed such references to the default resource resolution of the json-schema-validator library. A reference with a `classpath:` or `resource:` IRI made the PDP read the named resource from its class path, for example a configuration file packaged with the application, and use its content as a schema. The content could then be inferred from the outcome of the validation, and the detailed result of `jsonschema.validate` could return parts of it in its error messages. Whether references with `http`, `https`, `file` or `jar` URLs are fetched was left to the defaults of the library and not restricted by the engine. Had they been fetched, a schema could have made the PDP send requests to arbitrary addresses, including internal services and cloud metadata endpoints, or read local files.

You are affected if schemas or the arguments of the `jsonschema` functions can come from untrusted data, such as subscriptions, attribute data or a PDP configuration you do not control, or if you run policies written by untrusted authors, such as a public SAPL Playground.

The engine now resolves `$schema` and `$ref` only to the meta-schemas of the supported JSON Schema drafts (Draft 4, Draft 6, Draft 7, 2019-09 and 2020-12), which ship with the engine, and to schemas supplied with a matching `$id`: the `schemas` variable for `schema` statements, and the external schemas argument for the `jsonschema` functions. Any other reference fails without the engine opening a connection or reading a file or class path resource. A policy whose `schema` statement contains such a reference is rejected when it is compiled, and a `jsonschema` function returns an error. The error names the reference, never content of a resource.

Schemas that reference only the meta-schemas of the supported drafts and schemas supplied by their `$id` work as before. No action besides updating is needed.
